# 四路 GMSL 相机接入与 ACT 输入评估记录

日期：2026-06-29

本文记录四路 GMSL 超广角相机接入前的讨论结论，供现场安装、画面质量判断、后续数据记录和 ACT 输入适配使用。当前短期目标不是一次性完成最终多相机策略链路，而是先稳定看到画面，判断相机质量和安装位置，再用可回退的薄层代码改动支持迭代。

## 1. 当前判断

四路 GMSL 相机很可能比现有单目 FPV 更有价值，但不能默认一定优于单目。

潜在价值：

- 多视角可以减少单个 FPV 视角遮挡、阴影、局部土面纹理和视角漂移造成的输入不稳定。
- 不同安装位置可以分别覆盖铲斗/斗齿、土堆轮廓、作业区域、侧向姿态和末段回收状态。
- 对 ACT 来说，多视角有机会降低模型依赖某个局部阴影或单一 spurious cue 的风险。

主要风险：

- 四路图像会增加训练样本复杂度、显存、推理延迟和过拟合空间。
- 如果某一路经常被泥土、强反光、振动、遮挡或曝光漂移污染，它可能变成噪声源。
- 当前策略问题曾高度怀疑 FPV/image-chain mismatch，因此多相机接入必须保留离线消融，而不是只看训练 loss。

因此短期策略是：先接入并记录四路画面，但训练结论必须通过消融验证。至少比较：

- 单 `fpv` baseline。
- `fpv + 关键侧视/铲斗视角`。
- 四路全部输入。

评估指标应沿用策略效果窗口口径，例如起步、主动作段、末段多动和死区有效动作，而不是只看 val loss。

## 2. 现场优先级

短期核心任务按以下顺序执行：

1. 先看到四路画面。
2. 判断画面质量和安装位置。
3. 保存可复查样例。
4. 再决定训练输入形式和代码适配范围。

第一阶段不要求最终 ACT 多相机路径一次写好。代码修改可以同步做，但只服务现场试装和数据闭环，必须可回退、可改相机名、可改 ROI、可改安装位置。

## 3. 现场画面质量检查项

每个候选安装位置至少检查以下场景：

- home pose。
- 铲斗接近土堆。
- 入土。
- 装载。
- 回收/末段停机。
- 强光、阴影、局部反光。
- 机器振动和可能泥土遮挡。

每路相机重点判断：

- 是否看得到铲斗边缘、斗齿和土堆轮廓。
- 关键作业区域是否长期落在 190 度镜头畸变最严重的边缘。
- 遮挡是否频繁，是否容易被动臂、斗杆、铲斗或车体挡住。
- 曝光是否稳定，暗部和亮部是否还能保留任务相关细节。
- 画面是否被局部阴影、土面纹理或反光强烈主导。
- 震动时关键目标是否仍可辨认。

建议现场保存：

- 每路单帧 JPEG。
- 每路 10-30 秒短视频。
- 四路同一时刻 contact sheet。
- 相机名、分辨率、fps、时间戳、曝光/增益状态。
- 物理安装位置照片和安装版本说明。

## 4. 分辨率与 190 度超广角处理

相机本身是 3MP、190 度 HFOV。训练不建议直接使用四路 3MP 原图。

建议原则：

- 采集和复查尽量保留高质量原始画面。
- 训练使用固定、可复现、低分辨率的派生输入。
- 每路训练输入可先从 `320x240`、`384x216` 或相近量级开始，通过离线消融再调整。
- 降分辨率后必须确认铲斗边缘、斗齿、土堆轮廓和作业区域仍有足够像素。

不建议默认做完整 190 度全图到普通 pinhole 的去畸变。190 度画面超过普通透视模型的舒适范围，全图拉直会严重拉伸边缘，可能把关键区域变成不稳定视觉特征。

更推荐：

- 原始 fisheye 画面用于记录和排查。
- 每路根据任务区域生成固定 ROI 或 virtual view。
- 对需要几何判断的相机，使用局部 fisheye -> virtual pinhole/cylindrical 展开，再 resize。
- 对只提供全局上下文的相机，可以先尝试 raw fisheye resize。

训练和推理必须使用完全一致的图像变换，包括相机顺序、裁剪、resize、去畸变、颜色空间、padding 和归一化。所有变换需要版本化，避免同一 checkpoint 混用不同输入定义。

建议消融：

- `raw fisheye resized`。
- `ROI crop resized`。
- `rectified virtual view resized`。

## 5. 外参与标定

纯 ACT raw-image behavior cloning 不要求高精度外参才能运行。只要训练和推理看到同一相机顺序、同一安装姿态和同一图像变换，模型可以把每个视角当作独立视觉通道学习。

但仍建议做外参记录，至少达到工程可复现级。

原因：

- 方便换支架、重装相机后判断视角是否漂移。
- 方便 ROI/mask/virtual view 定义和复查。
- 方便排查某次训练或实车失败是否来自安装变化。
- 后续如果接 marker、3D、BEV 或跨相机几何融合，会直接需要外参。

如果相机固定在车体上，记录 `camera -> body/base` 外参。如果相机装在动臂、斗杆或铲斗等运动部件上，记录 `camera -> 所在 link` 的静态外参，再通过 qpos/运动学得到相对车体的动态关系。

建议同时记录：

- intrinsics 和 distortion model。
- camera name。
- mount/link name。
- extrinsic version。
- 标定日期。
- 标定板/方法。
- 重投影误差或简化质量指标。

## 6. 代码适配边界

短期代码目标是支持现场反复试位置，而不是一次性完成最终训练/推理方案。

第一阶段可做：

- 相机枚举和命名。
- 四路预览或抓帧入口。
- 单帧、短视频和 contact sheet 保存。
- 每路图像时间戳、分辨率、fps、编码格式和相机名记录。
- metadata 中记录 camera_names、intrinsics/extrinsics version、transform version。

暂不急于做：

- 把四路相机直接绑定成最终 ACT policy 输入。
- 改最终训练 schema 后立即淘汰单目 baseline。
- 在没有现场样例和离线消融前固定 ROI/去畸变策略。
- 为了一次性兼容所有未来安装位置而做大范围重构。

如果后续接入训练路径，原则是保持 `qpos[4] / qvel[4] / images` 的下游契约，扩展 `images` 下的相机名，而不是把相机逻辑散落到策略之外的多个不可追溯位置。

## 7. 现场输出物

这次现场结束后，理想输出物是：

- 四路相机是否都能稳定出图。
- 每路相机实际分辨率、fps、延迟和时间戳情况。
- 每个候选安装位置的 contact sheet。
- 明确推荐和不推荐的安装位置。
- 每路相机的主要用途判断，例如全局上下文、铲斗/斗齿、土堆侧向轮廓、末段回收。
- 是否需要调整支架、视角、曝光、ROI 或线缆固定。
- 后续代码适配的最小清单。

如果现场无法完成全部内容，优先保证四路原始样例和安装位置照片，因为这些是后续离线判断和代码适配的共同基础。
